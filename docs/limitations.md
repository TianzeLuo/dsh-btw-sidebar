# 已知限制

这些都是平台约束或刻意取舍，不是待修的 bug。设计动机见 [development.md](development.md)。

1. **面板打开期间，这条会话会出现在左侧会话列表里**（标题「侧边聊天 · …」）。
   平台硬约束：`ArchivedSessionGate` 在 session controller 里无条件装载
   （`dsh-api-session-controller/lib/index.js:2821`），已归档会话在 `agent/pre-step` 直接被 reject
   （同文件 `2384-2392`）。**要能干活就不能归档，不归档就会出现在列表里。** 关闭面板即归档，它随即消失。

2. **需要主会话至少有一个已完成的轮次**：没有完成轮次时 fork 没有切点，会返回一条可读错误
   （`FORK_FAILED`）。

3. **`/btw` 命令行本身不接受附件**（命令式输入不承载附件）。需要附件时，在打开的面板里用官方输入框发。

4. **归档后的会话仍在磁盘上**：可以在左侧列表切到「已归档」视图找到并恢复它——这也是「回收站」式的安全网。

5. **模型路由**：fork 用的是部署默认模型（`agentDefaultModel`），之后可在面板里用官方模型选择器切换。

6. **通知策略是宿主进程内的内存态**：dsh 重启后，从「已归档」手动恢复的旧侧边聊天会失去
   「看着不打扰 / 点通知回右栏」的待遇（重新开始提醒，点击也回主视图）。再用右栏面板打开它一次
   （`open`）就会补登记；归属主会话还能从 fork 血缘（`header.parentSession`）反推，所以补登记后
   的揭示目标仍能先切回原会话。会话 header 没有可扩展字段、`fork()` 也不接受标记位，没有官方原语
   可堵。详见 [notifications.md](notifications.md)。

7. **点击回右栏这条路的边界**：右栏服务缺失、没有 tab 类型认领那个 `dsh-resource://` 地址、
   或归属主会话的右栏没能在 3 秒内挂载过去时，点击退回「切到主视图那条会话」——宁可降级，也不让
   点击变成没反应；无论哪条失败路径，都不会把 tab 开进你当时正看着的那条会话的右栏。

8. **只支持 `web` profile**：客户端半部声明 `dsh.client.platform = "web"`，其他 app（headless 等）
   不会加载它；本插件依赖原生右侧栏、会话工厂槽与 `/` 触发管道，这些只在 `web` 下存在。
